SDK Fit

Breaking API changes, fixed and proven.

Finds the consumer call sites a breaking API change breaks, rewrites only the ones it can prove, runs your own checks, and opens a reviewed PR. No LLM in the analysis.

View on GitHub Install from PyPI See the demo

quickstart

$ pip install sdkfit
$ sdkfit check ./repo --old v1.yaml --new v2.yaml
$ sdkfit fix ./repo --old v1.yaml --new v2.yaml --check "pytest -q"

The analysis and proof run offline; only the final push and PR touch a remote.

Why

Evidence, not vibes.

Proof-first

Every patch states the strongest level that actually passed: TESTS_PASSED, CHARACTERIZED, REPLAYED or TYPES_BUILD_ONLY. Uncertain sites stay separate.

Deterministic and offline

No LLM in the analysis. The detector, locator, patch and proof run locally; the final push/PR uses your own git/gh or a GitHub App.

A provider path

A CLI for one repo, or a portable migration bundle and self-hosted service for a vendor migrating many customer repos.

How it works

From API diff to reviewed PR.

Two OpenAPI specs or MCP tool schemas.

02

Locate

Python, TypeScript/JavaScript, Rust, Go and C#.

03

Propose

Only the sites it can prove; the rest are listed.

04

Prove

Your own checks, before and after.

05

PR

Reviewed, never force-pushed or merged.

Proof

The diff is small. The proof is the point.

SDK Fit applies the patch to a copy and runs your own checks before and after. A report-bearing run is terminal; a failure with no report can retry within the configured budget.

  • TESTS_PASSED your test command passes before and after
  • CHARACTERIZED your characterization command passes
  • REPLAYED recorded calls replay successfully
  • TYPES_BUILD_ONLY the types build, and nothing more is claimed
